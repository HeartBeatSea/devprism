# Java 工程结构评审

## 步骤

1. 调 `repo_structure`，拿构建工具、Java 版本、主代码/测试类数量、模块数、依赖数。
2. 调 `search_repo` 查该项目自己的 README 或构建文件，确认它对构建方式的自述和目录推断是否一致。不一致时以文件内容为准，并说明差异。
3. 按下面四项给判断，每项都要带数字：
   - **构建**：Maven 还是 Gradle，有没有 wrapper（没有就是环境不一致的隐患）
   - **模块**：几层、哪些是业务模块、哪些是测试专用模块
   - **测试**：测试类与主代码类的比例。低于 0.3 提一句；完全没有 `src/test` 直接判为高风险
   - **依赖**：多模块项目要注意，根 POM 只是聚合器，别把它的依赖数当成全项目依赖数

## 注意

- **测试比例是类数量之比，不是行覆盖率。** 必须明说这一点，否则会被当成覆盖率数据。
- 如果没有 `src/main/java` 结构（比如纯 Kotlin 或非标准布局），先说无法判断，不要硬套。
- 目录树被 GitHub 截断时，所有计数都是下限，要标出来。
