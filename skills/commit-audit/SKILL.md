# 提交规范体检

## 步骤

1. 调 `commit_convention`，拿到规范率、违规样本和 Revert 占比。
2. **规范率低于 50% 时**，调 `search_knowledge` 查团队提交规范原文，后面必须引用它，不要凭印象说"应该用 Conventional Commits"。
3. 从违规样本里挑 2–3 条真实的提交信息贴出来当反例，比讲道理有用。
4. 结论分三段，缺一不可：
   - **现状**：规范率多少、样本量多大
   - **偏差**：最典型的两类违规是什么
   - **改法**：具体到工具，比如 commitlint + husky 拦截，而不是"建议规范提交"

## 注意

- 规范率的分母不含合并提交，如果样本量小于 20，先说样本不足，别下结论。
- 开源项目和本团队的规范未必一致，对照时要说清是"参考"不是"违规"。
- 不要按作者统计谁的规范率低。这个项目不用于个人考核。
