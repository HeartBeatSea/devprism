# PR 协作体检

## 步骤

1. 调 `pull_health`，拿新建/合并/未合并数量、合并周期中位数与 P90、无评审合并比例。
2. 如果「无评审合并比例」或「平均评审数」返回 `null`，**说明数据源没有评审记录**，这一项直接判为不可用，不要用 0 代替，也不要据此推测"没人评审"。
3. 合并周期看两个数：中位数说明典型情况，P90 说明长尾。两者差得远，说明有个别 PR 卡了很久，值得单独提。
4. 需要给改进建议时，调 `search_knowledge` 查团队的评审清单，引用原文。

## 判断口径

- 合并周期 > 72 小时：提"PR 停留偏久"
- P90 是中位数的 3 倍以上：说明流程不稳定，不是普遍慢而是个别卡死
- 未合并数持续增长：提出积压风险，但要说明这是窗口内的快照

## 注意

- 不要评价单个开发者的响应速度。
- 窗口内的数据不代表长期趋势，结论里要带上时间窗口。
- 评审强度不可用时，宁可少说一句，也不要编一个"评审不足"的结论。
