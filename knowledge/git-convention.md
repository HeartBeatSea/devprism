# Git 提交信息规范

本文档定义团队提交信息（commit message）的统一写法。摘要行建议不超过 72 个字符。

## 格式

采用 Conventional Commits 格式：

```
<类型>(<范围>): <主题>

<正文，可选>

<脚注，可选>
```

示例：

```
feat(parser): 支持嵌套数组解析
fix(auth): 修复 token 过期后未跳转登录页
```

## 类型取值

只允许以下类型，不得自造：

- `feat` 新功能
- `fix` 缺陷修复
- `docs` 仅文档变更
- `style` 格式调整，不影响逻辑
- `refactor` 重构，不改变外部行为
- `perf` 性能优化
- `test` 测试相关
- `build` 构建系统或依赖变更
- `ci` 持续集成配置
- `chore` 杂项
- `revert` 回滚

## 常见违规写法

以下写法一律视为不合规：

- `update` — 没有说明更新了什么
- `fix bug` — 没有说明修了哪个 bug
- `修改` — 中文且无类型前缀
- `WIP` — 临时提交不应进入主干
- `1234` — 纯数字或无意义字符串

## 与效能指标的关系

规范提交占比 = 符合上述格式的提交数 ÷ 总提交数，合并提交不计入分母。

该比例低于 50% 时，变更日志无法自动生成，回溯问题原因的成本显著上升。建议在提交钩子里做校验，而不是靠人自觉。
